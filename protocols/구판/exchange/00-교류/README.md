# 00-교류 — {{도구A}}와 {{도구B}}가 이 프로젝트를 주고받는 규칙

이 폴더는 두 AI 도구가 같은 프로젝트 폴더에서 일할 때 서로의 변경을 알리는 통로다.
사람({{사용자}})이 두 도구를 번갈아 쓰므로, 한쪽이 한 일을 다른 쪽이 다음 세션에서 바로 알 수 있어야 한다.
루트의 `AGENTS.md`({{도구B}}가 읽음)와 `CLAUDE.md`({{도구A}}가 읽음)는 이 문서를 가리킨다.

## 구성

| 파일·폴더 | 무엇 | 누가 고치나 |
|---|---|---|
| `현황.md` | 지금 무엇이 현행이고 다음에 무엇을 하는지. **단일 진실.** | 둘 다. 세션 끝에 갱신 |
| `LOG.md` | 시간순 대장. 한 세션에 한 줄 이상. | 둘 다. 위에 새 줄을 붙인다 |
| `{{도구A}}-to-{{도구B}}/` | {{도구A}}가 {{도구B}}에게 남기는 인계 노트 | {{도구A}}가 쓰고 {{도구B}}가 `status`를 바꾼다 |
| `{{도구B}}-to-{{도구A}}/` | {{도구B}}가 {{도구A}}에게 남기는 인계 노트 | {{도구B}}가 쓰고 {{도구A}}가 `status`를 바꾼다 |

## 세션을 시작할 때 (두 도구 공통)

1. `현황.md`를 읽는다. 어느 {{산출물}}의 어느 판이 현행인지, 누가 무엇을 맡고 있는지 여기서 확인한다.
2. `LOG.md`의 위쪽 열 줄을 읽는다.
3. 자기 앞으로 온 폴더에서 `status: 대기`인 노트를 전부 읽는다.
4. 읽은 노트의 `status`를 `확인`으로 바꾸고, 확인한 날짜를 `read:` 줄에 적는다. 그 노트에 요청 사항이 있으면 이번 세션의 할 일에 넣는다.
5. `git log --oneline -20`으로 상대가 남긴 커밋을 본다. 파일 단위 변경은 여기서 확인한다.

## 세션을 마칠 때 (두 도구 공통)

1. 바꾼 것이 있으면 인계 노트를 한 장 쓴다. 파일명은 `YYYY-MM-DD-NN-주제.md` (NN은 그날의 일련번호, 01부터). 형식은 `인계노트-양식.md`.
2. `현황.md`를 고친다. 현행 판이 바뀌었으면 반드시 고친다.
3. `LOG.md` 맨 위에 한 줄을 붙인다.
4. git 커밋한다. 메시지 첫머리에 `[{{도구A}}]` 또는 `[{{도구B}}]`를 붙인다.

## 충돌을 피하는 규칙

- **같은 {{산출물}}을 동시에 고치지 않는다.** `현황.md`의 "담당" 칸에 적힌 쪽만 고친다. 담당을 바꾸려면 인계 노트에 적고 `현황.md`를 고친다. 담당이 아닌 쪽은 심사나 의견까지만 낸다.
- **현행 판의 위치는 `현황.md`에만 적는다.** 다른 문서가 어긋나면 `현황.md`가 맞다.
- **파일을 새 판으로 올릴 때는 지난 판을 지우지 않고 그 폴더의 `구판/`으로 내린다.**
- **{{금지행위}}는 사용자 확인 후에만 한다.** 그 직전 단계까지 준비하고 노트에 적는다.
- **상대가 만든 파일을 지우거나 크게 옮길 때는 먼저 노트로 알린다.**
- **{{코드저장소}}에 프로젝트 이름이나 AI 흔적을 남기지 않는다.**

## git 규칙

- 저장소는 프로젝트 루트다. 첫 커밋 `{{기준선 해시}}`가 도입 전 상태다.
- 20MB 넘는 원자료는 폴더에 두되 git에는 넣지 않는다.
- 이력을 고쳐 쓰지 않는다(`rebase -i`, `push --force` 금지). 잘못 커밋했으면 되돌리는 커밋을 새로 만든다.
- 커밋은 작업 단위마다 한다. 하루 한 번 몰아서 하면 상대가 중간 상태를 못 본다.
- 어느 도구의 작업 환경이 파일을 못 지우면 git이 `index.lock`이나 `objects/*/tmp_obj_*`를 못 지워 멈춘다. 그때는 사용자에게 삭제 권한을 요청한 뒤 지우고 다시 한다. LOG의 커밋 칸이 "미커밋"이면 파일은 바뀌었는데 git에 없다는 뜻이므로 상대가 `git status`로 확인한다.
