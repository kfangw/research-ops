# 이 프로젝트에서 일하는 AI 도구를 위한 규칙

이 폴더는 {{사용자}}의 {{프로젝트}}이다.
{{도구1}}와 {{도구2}}, 두 도구가 같은 저장소에서 번갈아 일하며, 서로의 변경은 git과 `00-교류/`로 전달한다.<!--두도구-->
{{도구1}}가 이 저장소에서 일하며, 세션마다 기록을 `00-교류/`에 남긴다.<!--한도구-->
기준은 GitHub의 `main`이다. 사용자 컴퓨터의 폴더와 각 도구의 클라우드 작업 공간은 모두 클론이다.

## 세션을 시작하면

1. 원격(origin)이 있으면 `git pull --rebase origin main`. 충돌이 나면 원격의 것을 살리고 내 것을 다시 적는다. `docs/설정.md`의 운영 체계 절에 적힌 주기로 운영 체계의 새 판을 확인한다(research-session 1절 3번).
2. `00-교류/현황.md`를 읽는다. 어느 {{산출물}}의 어느 판이 현행이고 누가 맡고 있는지는 여기가 기준이다.
3. `00-교류/log/`에서 가장 최근 세 파일을 읽는다.
   자기 앞으로 온 인계 노트(`status: 대기`)를 읽고 `status`를 `확인`으로 바꾼다.<!--두도구-->
4. `git log --oneline -20`으로 다른 세션의 커밋을 본다.
5. `git fetch origin` 뒤 `origin/away/*` 브랜치에 사용자 표시가 비어 있는 검토서가 있으면 먼저 사용자에게 보인다.
6. 프로젝트 지도는 `README.md`. 할 일은 `docs/할일목록.md`, 결정과 판정은 `docs/승인기록.md`.

## 세션을 마치면

다른 도구에게 알릴 것이 있으면 인계 노트를 쓴다.<!--두도구-->
`현황.md`를 갱신하고, 사용자가 한동안 자리를 비우면 맡길 일이 있는지 제안하고(research-batch 8.1), `00-교류/log/`에 세션 파일 하나를 남기고, 도구 이름을 접두로 붙여(예: `[{{도구1}}]`) 커밋한 뒤 `git push origin main`한다.
push가 거절되면 다시 pull --rebase 하고 push한다. force push는 하지 않는다.
형식과 자세한 규칙은 `00-교류/README.md`.

## 지켜야 할 것

- {{산출물}}마다 `현황.md`의 담당 칸에 적힌 쪽만 고친다. 담당이 아니면 심사와 의견까지만.<!--두도구-->
- 새 판을 만들면 지난 판은 같은 폴더의 `구판/`으로 내린다. 지우지 않는다.
- 사용자 확인 후에만 하는 일: {{금지행위}}. 그 직전 단계까지만 준비한다.
- 다른 도구가 만든 파일을 지우거나 옮길 때는 인계 노트에 적는다.<!--두도구-->
- `.env`, 키 파일, `data/raw/`, `results/raw/`는 커밋하지 않는다. `.gitignore`가 뺀 큰 파일을 강제로 넣지 않는다.
- 사용자 컴퓨터의 `code/scripts/autosync.sh`가 주기적으로 `[mac-auto]` 커밋을 만들어 push할 수 있다. 그 커밋은 백업이지 작업 단위가 아니다. 세션은 작업 단위마다 커밋하고, 시작할 때 `git pull --rebase`로 먼저 받는다.
- git 이력을 고쳐 쓰지 않는다. 잘못되면 되돌리는 커밋을 새로 만든다.
- 진행은 research-session 스킬 8절의 틀(시작 안내, 진행판, 마침 보고)과 상태어로 보인다. 사용자가 보는 곳에 5분 넘게 아무 표시도 없게 두지 않는다.
- 사용자가 자리를 비운 동안의 작업은 승인된 `docs/맡김/<시작>-지시서.md`가 있을 때만 하고 `away/<시작>` 브랜치에만 커밋한다(`docs/설정.md`에서 바꿀 수 있다). 사용자 검토 전에 main에 합치지 않는다. 절차는 research-batch 스킬 8절.
- 이 저장소는 작업 저장소다. 투고용 artifact는 `code/scripts/export-artifact.sh`로 `code/`만 새 이력으로 뽑아 별도 저장소에 낸다. 그 저장소에는 프로젝트 이름, 사용자 이름, AI 흔적을 남기지 않는다.
- 국문 문서는 담백한 학술 문어로 쓴다. 산문 속 기호(·, —, →), "핵심은 ~다"류 강조 공식, 번역투 피동을 쓰지 않는다. 영어 용어는 영문 그대로 둔다. 영문 원고는 프로젝트의 영문 학술 문체 규범을 따른다.
