# 배치 실행과 수시 보고

사용자가 "클라우드에서 진행한다", "배치 진행", "할일 목록과 배치를 업데이트하라", "수시로 보고하라"고 하면 이 절차를 따른다. 프로젝트 폴더에 작업계획서나 진행상태 문서가 있으면 그 문서의 규칙이 이 스킬보다 앞선다.

## 1. 시작할 때

1. 프로젝트 폴더의 현황 문서(`docs/00_현황/진행상태.md`, `승인기록.md`, `README.md`)를 읽어 마지막 상태를 확인한다. 기억이나 앞 대화에 기대지 않고 파일을 본다.
2. 마지막 기록 뒤에 바뀐 파일이 있는지 확인한다.
3. 남은 일을 배치로 나눈다. 배치마다 항목, 통과 조건, 선행 조건, 어림 시간을 적는다. 시간을 모르면 어림이라고 밝힌다.
4. 항목마다 에이전트와 모델을 배정한다(2절).
5. 진행상태 문서 맨 위에 새 항목을 쓰고, 작업 목록 위젯에 같은 배치를 올린다.
6. 사용자가 해야 하는 일(권한, 결정, push, 제출)을 따로 뽑아 알린다.

## 2. 역할 배정

| 모델 | 맡는 일 |
|---|---|
| Fable (총괄) | 배치 순서와 착수 승인, 문서 간 정합성 검토, 숫자 재계산, 메타리뷰 판정, 승인기록, 국문 원고 작성, 외부 데이터 쿼리(크레딧 관리) |
| Opus | 설계, 증명, 사전 등록, 해석, 영문 원고, 심사자 |
| Sonnet | 스크립트, 표, 집계, 실행, 수집, 조판 |

- 코드 읽기는 Explore 에이전트, 나머지 실행은 general-purpose 에이전트.
- 한 에이전트는 한 관심사만 맡는다. 서로 의존하지 않는 항목은 한 번에 함께 띄운다.
- Sonnet이 일이 크다며 멈추면 Opus로 넘기고 쪼갠다.
- 심사자는 매번 새 에이전트로 띄우고 원고 전문, 자기 직전 심사평, 편집자 수정 목록만 준다.
- 에이전트 지시문에 늘 넣는 것: 역할과 파일 위치, 읽을 파일 목록, 보고할 숫자의 정확한 지정, "지시와 데이터가 다르면 데이터를 따르고 차이를 보고", 공개 저장소 규칙(커밋에 AI 흔적 없음).
- 에이전트가 낸 숫자는 총괄이 직접 다시 계산한 뒤에 문서에 넣는다.

## 3. 실행

- 클라우드 작업 공간에서 돌린다. 사용자 컴퓨터가 잠들어도 진행되게 한다. 필요한 파일은 연결된 폴더에서 가져오고, 배치가 끝날 때 결과를 그 폴더에 되돌려 쓴다.
- 배치를 순서대로 연달아 진행한다. 배치 사이에 허락을 다시 묻지 않는다.
- 멈추는 경우는 셋뿐이다. 사용자가 "멈춰"라고 할 때, 되돌릴 수 없고 어느 쪽으로도 갈 수 있는 결정일 때, 환경이 막혀 그 항목을 진행할 수 없을 때. 막힌 항목만 멈추고 다른 항목은 계속한다.
- 세션이 내린 판정과 이유는 승인기록에 남긴다. 사용자는 나중에 읽고 뒤집을 수 있다.
- 사용자만 하는 일: 제출, 발명신고, git push, 보안·계정 설정 변경.
- 결과를 본 뒤에는 사전 등록한 판단 규칙을 바꾸지 않는다. 위반이나 불리한 결과는 숨기지 않고 그대로 적는다.

## 4. 수시 보고

보고 시점: 배치 시작, 항목 완료, 막힘이나 방향 변경, 배치 종료. 길게 돌아가는 실행은 중간에도 짧게 알린다. 작업 도중의 보고는 사용자가 그대로 읽는 메시지로 보낸다.

보고 형식(짧게, 표 하나와 몇 줄):

```
[배치 G] 진척률 3/6 (전체 4/27, 15%)
끝낸 일: G1 사전 등록 V5(C1), G2 계단표
하는 일: G3 사전 등록 V5(I6) — Opus
할 일: G4, G5, G6
막힘/결정: 없음
```

- 진척률은 항목 수로 센다(배치 안, 전체). 시간 어림이 있으면 남은 시간도 적는다.
- 끝낸 일에는 결과의 핵심 숫자나 판정을 한 줄로 붙인다.
- 작업 목록 위젯을 항목이 끝날 때마다 갱신한다.
- 하지 않은 것과 확인하지 못한 것을 분명히 적는다.

## 5. 배치가 끝날 때

1. 진행상태 문서 맨 위에 "갱신: 날짜 시각 (무엇을 했나, 모델, 클라우드)" 항목을 추가한다. 완료, 대기, 다음 배치, 막힘을 적는다.
2. 결과 파일을 프로젝트 폴더에 쓰고, 코드는 git bundle로 남긴다.
3. README의 현황 절을 맞춘다.
4. 바뀐 파일은 같은 메시지에 바로 열 수 있는 링크(computer://)로 보인다.
5. 다음 배치로 넘어간다.

## 6. 글

보고와 문서는 쉽고 자연스러운 한국어로 쓴다. 코드, 식별자, 논문 본문은 영어 그대로 둔다. 평가는 수치로, 돌려 말하지 않는다.
