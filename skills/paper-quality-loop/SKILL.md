# 논문 품질 반복

원고를 "심사 → 분류 → 실행 → 문체"의 바퀴로 돌리고, 시작 전에 적어 둔 기준에 닿으면 멈춘다. 이 스킬은 순서와 멈춤 규칙만 정한다. 각 단계의 방법은 기존 스킬을 따른다.

| 단계 | 따르는 스킬 |
|---|---|
| 주장과 증거, 초록·서론·결론 | paper-framing |
| 배치 실행과 보고 | batch-run-report |
| 할일목록 새 판본 | paper-todo-update (배치 구조가 바뀔 때만) |
| 문체 | english-academic-style, 국문은 korean-academic-style |
| 쪽 수 맞춤 | paper-condense |

프로젝트 폴더에 작업계획서, 진행상태, 사전 등록 문서가 있으면 그 규칙이 이 스킬보다 앞선다.

## 0. 시작할 수 있는 조건

아래 가운데 하나라도 안 맞으면 바퀴를 돌리지 않고 이유를 사용자에게 알린다.

- 처음부터 끝까지 읽히는 초안이 있다. 결과 절이 비어 있으면 심사가 아니라 실험 배치가 먼저다.
- 원고의 범위(주장 목록, 넣을 것과 뺄 것)가 정해져 있다. 없으면 paper-framing 0절의 주장 목록부터 만든다.
- 원고를 막고 있는 사용자 결정이 없다. 있으면 그 결정을 먼저 묻는다.
- 마감과 쪽 수 상한을 안다.

## 1. 멈춤 기준을 먼저 적는다

첫 바퀴 전에 기준을 `<원고 폴더>/품질반복/기준.md`에 적고 사용자에게 보인다. 사용자가 따로 정하지 않으면 아래 기본값을 쓴다. 바퀴가 돈 뒤에는 기준을 낮추지 않는다. 바꾸려면 사용자가 정하고 승인기록에 남긴다.

| 기준 | 기본값 | 재는 쪽 |
|---|---|---|
| 증거가 감당 못 하는 주장 | 0개 | 총괄 (paper-framing 0절 주장 목록) |
| 원고 숫자와 원자료의 불일치 | 0개 | 독립 검산 |
| 큰 지적 | 심사자 모두 0개 | 심사 |
| 새 독자가 막힌 곳 | 3곳 이하 | 새 독자 |
| 쪽 수, 단어 수, 양식 | 투고처 규정 충족 | 총괄 |
| 횟수 상한 | 학회 판본 2바퀴, 학술지 판본 3바퀴 | |

작은 지적이 남아도 멈춘다. 심사 에이전트는 몇 번을 돌려도 지적을 내므로 "지적 0개"를 기준으로 삼지 않는다.

**큰 지적**: 주장을 증거가 받치지 못한다, 증명이나 계산이 틀렸다, 전제가 숨어 있어 결론이 달라질 수 있다, 비교군이 없어 결론을 내릴 수 없다, 가장 가까운 선행 연구와의 차이가 불분명하다, 재현에 필요한 정보가 없다.
**작은 지적**: 문장, 배치, 설명 부족, 용어 불일치, 그림과 표의 가독성.

## 2. 한 바퀴

### 2.1 심사

네 에이전트를 한 번에 함께 띄운다. 모두 새로 띄우고 앞선 대화와 이전 바퀴의 심사평을 넘기지 않는다.

| 역할 | 모델 | 받는 것 | 내는 것 |
|---|---|---|---|
| 심사 ×2 (학술지는 ×3) | Opus | 익명 원고, 투고처의 심사 기준 | 지적 목록(크기, 위치, 근거), 판정(수락, 소수정, 대수정, 거절) |
| 새 독자 | Sonnet | 익명 원고 | 비전문가로 읽어 막힌 곳과 이유만 |
| 숫자 검산 | Sonnet | 원고, 규칙 문서, 원자료 | 원고의 모든 숫자를 다시 계산한 대조표 |

- 심사자에게 지적마다 "크다, 작다"와 그 이유를 적게 한다. 1절의 정의를 지시문에 넣는다.
- 심사자에게 고칠 문장을 써 달라고 하지 않는다. 지적만 받는다.
- 마지막 바퀴에는 가능하면 다른 계열 모델의 심사를 한 번 넣는다. 같은 계열은 놓치는 곳이 겹친다. 프로젝트에 교류 규약(00-교류)이 있으면 그 절차로 맡긴다.

### 2.2 분류 (총괄)

총괄이 지적을 하나씩 표로 옮긴다. 열은 번호, 낸 쪽, 크기, 위치, 종류, 처리, 담당이다.

| 종류 | 처리 |
|---|---|
| 주장·증거 | paper-framing 0절의 주장 목록으로 돌아간다. 증거를 더할 수 없으면 주장을 줄인다 |
| 실험 | 새 실험이나 재집계가 필요하다. 마감 안에 되는지 어림하고, 안 되면 주장을 줄이거나 한계에 적는다 |
| 사실·숫자 | 원자료에서 총괄이 직접 다시 계산해 고친다 |
| 문장·구조 | 해당 문단만 고친다 |
| 받지 않음 | 이유를 한 줄 적는다. 큰 지적은 근거 없이 받지 않을 수 없다 |

- 심사자가 크다고 한 지적을 총괄이 작다고 낮추려면 이유를 적는다.
- 주장을 바꾸는 판단은 총괄만 하고 승인기록에 남긴다. 원고의 주장을 바꾸는 일은 사용자에게 묻는다.
- 결과를 본 뒤에는 사전 등록한 판단 규칙을 바꾸지 않는다. 불리한 결과를 빼서 지적을 닫지 않는다.
- 분류가 끝나면 1절 기준으로 판정한다. 모두 충족이면 3절로 간다.

### 2.3 실행

- batch-run-report 절차로 고친다. 진척을 수시로 보고하고 작업 목록 위젯에 올린다.
- 원고 수정은 Opus, 집계와 조판은 Sonnet. 고친 에이전트가 자기 수정을 채점하지 않는다.
- 배치 구조나 일정이 바뀔 때만 paper-todo-update로 할일목록을 새 판본으로 만든다. 바퀴마다 만들지 않는다.
- 초록, 서론, 결론을 고칠 때는 paper-framing 5절(심사 대응 이동 기록)을 지킨다. 이전 바퀴에서 닫은 지적이 다시 열리지 않았는지 대조한다.

### 2.4 문체

- 이번 바퀴에서 바뀐 문단에만 문체 스킬을 적용한다.
- 전체 적용은 원고를 고정하기 직전에 한 번만 한다. 문체 수정은 사실을 바꿀 수 있으므로, 적용 뒤 원문과 대조해 숫자, 부등호, 인용, 조건이 그대로인지 확인한다.
- 쪽 수가 넘치면 paper-condense로 줄인다.

### 2.5 바퀴 기록

`<원고 폴더>/품질반복/R<번호>/`에 심사평 원문, 분류표, 검산 대조표, 판정을 둔다. 진행상태 문서 맨 위에 한 항목을 더한다. 통째로 덮어쓰지 않는다.

## 3. 멈춤과 보고

바퀴가 끝날 때마다 아래 형식으로 보고한다.

```
[품질반복 R2] 기준 4/5 충족
큰 지적: 심사1 0, 심사2 1 (정리 1 전제) → 미충족
감당 못 하는 주장 0 / 숫자 불일치 0 / 새 독자 막힘 2 / 쪽 수 10/10
이번 바퀴에 닫은 지적 14 (큰 것 3), 남은 지적 6 (큰 것 1)
다음: R3 (상한 3 가운데 3번째) 또는 사용자 결정
```

- **기준을 모두 채우면** 멈춘다. 전체 문체 적용과 대조를 한 번 하고 원고를 고정한다(해시 기록).
- **횟수 상한에 닿았는데 못 채우면** 더 돌리지 않는다. 남은 큰 지적과 선택지(그대로 제출, 주장이나 범위 축소, 제출 연기)를 사용자에게 보이고 결정을 받는다.
- **마감까지 남은 날이 한 바퀴에 드는 날보다 적으면** 새 바퀴를 시작하지 않는다.
- **두 바퀴 연속으로 같은 큰 지적이 남으면** 문장으로 풀리는 문제가 아니다. 주장을 줄이거나 실험을 더할지 사용자에게 묻는다.

## 4. 지킬 것

- 만든 쪽이 채점하지 않는다. 심사와 검산은 매번 새 에이전트다.
- 에이전트가 낸 숫자는 총괄이 다시 계산한 뒤에 원고에 넣는다.
- 없는 사실, 숫자, 인용을 만들어 지적을 닫지 않는다.
- 제출, push, 계정 작업은 사용자가 한다.
- 보고와 문서는 쉬운 한국어로, 평가는 숫자로 쓴다. 논문 본문과 식별자는 영어 그대로 둔다.
- 새로 만들거나 고친 파일은 같은 답에 computer:// 링크로 보인다.
