# AI 도구 교류 규약

사람이 두 AI 도구를 번갈아 쓰는 프로젝트에서, 한쪽이 한 일을 다른 쪽이 다음 세션에서 바로 알게 하는 규약이다. 두 도구는 서로 대화하지 않는다. 프로젝트 파일과 git 커밋이 유일한 통로다.

## 언제 쓰나

- 사용자가 "교류 구조", "00-교류", "ChatGPT와 소통 규칙", "인계 노트"를 새 프로젝트에 넣어 달라고 할 때 → **설치** 절차.
- 프로젝트 루트에 `00-교류/`나 `CLAUDE.md`에 이 규약이 이미 있을 때 → **세션 절차**를 따른다. 사용자가 말하지 않아도 따른다.

## 세션 절차 (규약이 이미 있는 프로젝트)

시작할 때, 이 순서대로:
1. `00-교류/현황.md`를 읽는다. 어느 산출물의 어느 판이 현행이고 누가 맡았는지는 여기가 기준이다. 다른 문서와 어긋나면 현황.md가 맞다.
2. `00-교류/LOG.md` 위쪽 열 줄을 읽는다.
3. 자기 앞으로 온 폴더(`chatgpt-to-claude/` 등)에서 `status: 대기`인 노트를 전부 읽고, `status`를 `확인`으로, `read:`에 날짜를 적는다. 요청 사항은 이번 할 일에 넣는다.
4. `git log --oneline -20`으로 상대 커밋을 본다.

끝낼 때, 넷을 빠짐없이:
1. 바꾼 게 있으면 인계 노트 한 장 (`보낸쪽-to-받는쪽/YYYY-MM-DD-NN-주제.md`, 아래 양식).
2. `현황.md` 갱신. 현행 판이 바뀌었으면 반드시.
3. `LOG.md` 맨 위에 한 줄.
4. `[claude]` 접두 커밋. 작업 단위마다, 몰아서 하지 않는다.

지킬 것:
- 현황의 담당 칸에 적힌 쪽만 그 산출물을 고친다. 담당이 아니면 심사와 의견까지만.
- 새 판을 올리면 지난 판은 `구판/`으로 내린다. 지우지 않는다.
- 실험 실행 등 금지행위는 사용자 확인 후에만. 그 직전 단계까지만 준비.
- 상대 파일을 지우거나 옮기면 노트로 알린다.
- 코드 저장소에 프로젝트 이름이나 AI 흔적을 남기지 않는다.
- git 이력을 고쳐 쓰지 않는다. 잘못되면 되돌리는 커밋.
- Cowork VM은 파일을 못 지우므로 git이 `index.lock`, `objects/*/tmp_obj_*`, `HEAD.lock` 때문에 멈추면 `device_request_delete_permission`(프로젝트 루트)을 요청한 뒤 지운다. 경고만 나고 커밋이 됐으면 잔여물을 현황의 "폴더 안의 잔여물"에 적는다.
- LOG의 커밋 칸이 "미커밋"이면 파일은 바뀌었는데 git에 없다는 뜻이다. `git status`로 확인한다.

## 설치 절차 (새 프로젝트)

1. 사용자에게 자리표시자 값을 묻거나 대화에서 확정한다. 모르면 원 프로젝트 값을 예로 보여 준다.

| 자리표시자 | 뜻 | 예 |
|---|---|---|
| `{{프로젝트}}` | 폴더가 무엇인지 한 줄 | 박사 연구 문서·원고·실험 기록 |
| `{{사용자}}` | 두 도구를 쓰는 사람 | <사용자> |
| `{{도구A}}`, `{{도구B}}` | 커밋 접두와 폴더명에 쓸 소문자 이름 | claude, chatgpt |
| `{{산출물}}` | 담당을 나누는 단위 | 원고 |
| `{{코드저장소}}` | 문서 폴더 밖 별도 저장소 | <코드저장소> |
| `{{금지행위}}` | 사용자 확인 없이 하면 안 되는 일 | 실험 실행 |

2. 아래 파일들을 만든다. 자리표시자는 채워서 쓴다. `CLAUDE.md`는 `AGENTS.md`와 같은 내용.
3. 노트 폴더 `00-교류/{{도구A}}-to-{{도구B}}/`, `00-교류/{{도구B}}-to-{{도구A}}/`를 `.gitkeep`과 함께 만든다.
4. 루트에 git 저장소가 없으면 `git init` 후 도입 전 상태를 첫 커밋으로 만들고 그 해시를 `00-교류/README.md` git 절에 적는다. 있으면 현재 HEAD를 기준선으로 적는다.
5. `현황.md` 표에 산출물별 현행 판과 담당을 채운다. 미정이면 "미정".
6. 첫 인계 노트 `{{도구A}}-to-{{도구B}}/YYYY-MM-DD-01-교류구조-도입.md`를 쓰고, LOG 한 줄, `[{{도구A}}] 교류 구조 도입` 커밋.
7. 국문 문서는 담백한 학술 문어로 쓴다. 산문 속 기호(·, —, →), "핵심은 ~다"류 강조, 번역투 피동을 쓰지 않는다. 사용자가 이 문체 규칙을 원하지 않는 프로젝트면 AGENTS.md 마지막 항목을 뺀다.

### 파일: `AGENTS.md` (= `CLAUDE.md`)

```markdown
# 이 프로젝트에서 일하는 AI 도구를 위한 규칙

이 폴더는 {{사용자}}의 {{프로젝트}}이다.
{{도구A}}와 {{도구B}}가 같은 폴더에서 번갈아 일하며, 서로의 변경은 `00-교류/`로 전달한다.

## 세션을 시작하면

1. `00-교류/현황.md`를 읽는다. 어느 {{산출물}}의 어느 판이 현행이고 누가 맡고 있는지는 여기가 기준이다.
2. `00-교류/LOG.md` 위쪽 열 줄과, 자기 앞으로 온 인계 노트(`status: 대기`)를 읽고 `status`를 `확인`으로 바꾼다.
3. `git log --oneline -20`으로 상대의 커밋을 본다.
4. 프로젝트 지도가 필요하면 `INDEX.md`.

## 세션을 마치면

인계 노트를 쓰고, `현황.md`와 `LOG.md`를 갱신하고, `[{{도구A}}]` 또는 `[{{도구B}}]` 접두를 붙여 커밋한다.
형식과 자세한 규칙은 `00-교류/README.md`.

## 지켜야 할 것

- `현황.md`의 담당 칸에 적힌 쪽만 그 {{산출물}}을 고친다.
- 새 판을 만들면 지난 판은 같은 폴더의 `구판/`으로 내린다. 지우지 않는다.
- {{금지행위}}는 사용자 확인 후에만 한다. 그 직전 단계까지만 준비한다.
- 상대가 만든 파일을 지우거나 옮길 때는 인계 노트에 적는다.
- {{코드저장소}}에 프로젝트 이름이나 AI 흔적을 남기지 않는다.
- git 이력을 고쳐 쓰지 않는다. `.gitignore`가 뺀 큰 파일을 강제로 넣지 않는다.
- 국문 문서는 담백한 학술 문어로 쓴다. 산문 속 기호(·, —, →), "핵심은 ~다"류 강조 공식, 번역투 피동을 쓰지 않는다. 영어 용어는 영문 그대로 둔다.
```

### 파일: `.gitignore` (없으면 만들고, 있으면 덧붙임)

```
# {{코드저장소}}/   자체 저장소를 가진 하위 폴더
_to_delete*/
__pycache__/
.venv/
tmp/
.DS_Store
*.tar.gz
*-reproducibility*.zip
raw-results*/
```

### 파일: `00-교류/README.md`

```markdown
# 00-교류 — {{도구A}}와 {{도구B}}가 이 프로젝트를 주고받는 규칙

이 폴더는 두 AI 도구가 같은 프로젝트 폴더에서 일할 때 서로의 변경을 알리는 통로다.
사람({{사용자}})이 두 도구를 번갈아 쓰므로, 한쪽이 한 일을 다른 쪽이 다음 세션에서 바로 알 수 있어야 한다.
루트의 `AGENTS.md`({{도구B}}가 읽음)와 `CLAUDE.md`({{도구A}}가 읽음)는 이 문서를 가리킨다.

## 구성

| 파일·폴더 | 무엇 | 누가 고치나 |
|---|---|---|
| `현황.md` | 지금 무엇이 현행이고 다음에 무엇을 하는지. **단일 진실.** | 둘 다. 세션 끝에 갱신 |
| `LOG.md` | 시간순 대장. 한 세션에 한 줄 이상. | 둘 다. 위에 새 줄을 붙인다 |
| `{{도구A}}-to-{{도구B}}/` | {{도구A}}가 {{도구B}}에게 남기는 인계 노트 | {{도구A}}가 쓰고 {{도구B}}가 `status`를 바꾼다 |
| `{{도구B}}-to-{{도구A}}/` | {{도구B}}가 {{도구A}}에게 남기는 인계 노트 | {{도구B}}가 쓰고 {{도구A}}가 `status`를 바꾼다 |

## 세션을 시작할 때 (두 도구 공통)

1. `현황.md`를 읽는다. 어느 {{산출물}}의 어느 판이 현행인지, 누가 무엇을 맡고 있는지 여기서 확인한다.
2. `LOG.md`의 위쪽 열 줄을 읽는다.
3. 자기 앞으로 온 폴더에서 `status: 대기`인 노트를 전부 읽는다.
4. 읽은 노트의 `status`를 `확인`으로 바꾸고, 확인한 날짜를 `read:` 줄에 적는다. 그 노트에 요청 사항이 있으면 이번 세션의 할 일에 넣는다.
5. `git log --oneline -20`으로 상대가 남긴 커밋을 본다. 파일 단위 변경은 여기서 확인한다.

## 세션을 마칠 때 (두 도구 공통)

1. 바꾼 것이 있으면 인계 노트를 한 장 쓴다. 파일명은 `YYYY-MM-DD-NN-주제.md` (NN은 그날의 일련번호, 01부터). 형식은 `인계노트-양식.md`.
2. `현황.md`를 고친다. 현행 판이 바뀌었으면 반드시 고친다.
3. `LOG.md` 맨 위에 한 줄을 붙인다.
4. git 커밋한다. 메시지 첫머리에 `[{{도구A}}]` 또는 `[{{도구B}}]`를 붙인다.

## 충돌을 피하는 규칙

- **같은 {{산출물}}을 동시에 고치지 않는다.** `현황.md`의 "담당" 칸에 적힌 쪽만 고친다. 담당을 바꾸려면 인계 노트에 적고 `현황.md`를 고친다. 담당이 아닌 쪽은 심사나 의견까지만 낸다.
- **현행 판의 위치는 `현황.md`에만 적는다.** 다른 문서가 어긋나면 `현황.md`가 맞다.
- **파일을 새 판으로 올릴 때는 지난 판을 지우지 않고 그 폴더의 `구판/`으로 내린다.**
- **{{금지행위}}는 사용자 확인 후에만 한다.** 그 직전 단계까지 준비하고 노트에 적는다.
- **상대가 만든 파일을 지우거나 크게 옮길 때는 먼저 노트로 알린다.**
- **{{코드저장소}}에 프로젝트 이름이나 AI 흔적을 남기지 않는다.**

## git 규칙

- 저장소는 프로젝트 루트다. 첫 커밋 `{{기준선 해시}}`가 도입 전 상태다.
- 20MB 넘는 원자료는 폴더에 두되 git에는 넣지 않는다.
- 이력을 고쳐 쓰지 않는다(`rebase -i`, `push --force` 금지). 잘못 커밋했으면 되돌리는 커밋을 새로 만든다.
- 커밋은 작업 단위마다 한다. 하루 한 번 몰아서 하면 상대가 중간 상태를 못 본다.
- 어느 도구의 작업 환경이 파일을 못 지우면 git이 `index.lock`이나 `objects/*/tmp_obj_*`를 못 지워 멈춘다. 그때는 사용자에게 삭제 권한을 요청한 뒤 지우고 다시 한다. LOG의 커밋 칸이 "미커밋"이면 파일은 바뀌었는데 git에 없다는 뜻이므로 상대가 `git status`로 확인한다.
```

### 파일: `00-교류/현황.md`

```markdown
# 현황 — 무엇이 현행이고 다음에 무엇을 하나

*마지막 갱신: YYYY-MM-DD (누가, 한 줄 요약). 세션을 시작하면 이 파일부터 읽는다. 어긋나는 문서가 있으면 이 파일이 맞다.*

## {{산출물}}별 현행 판과 담당

| {{산출물}} | 현행 판 | 위치 | 담당 | 상태 |
|---|---|---|---|---|
| (이름, 목적지나 마감) | (판 번호) | (정본 경로) | {{도구A}} / {{도구B}} / 미정 | (한 줄) |

## 방침 (사용자 결정, 날짜순)

- YYYY-MM-DD: (사용자가 정한 것. 도구의 권고안과 구별해 적는다)

## {{산출물}}별 남은 일

### (이름)

- (다음에 할 일. 누가 하는지, 사용자 판단이 필요한지 표시)

## 폴더 안의 잔여물 (사용자가 지울 것)

- (도구가 못 지운 임시 파일, lock 파일 등)
```

### 파일: `00-교류/LOG.md`

```markdown
# 교류 대장 (최신이 위)

| 날짜 | 누가 | 커밋 | 한 줄 요약 | 노트 |
|---|---|---|---|---|
| YYYY-MM-DD | {{도구A}} | 이 행을 포함한 커밋 | 교류 구조 도입 | `{{도구A}}-to-{{도구B}}/YYYY-MM-DD-01-교류구조-도입.md` |
```

### 파일: `00-교류/인계노트-양식.md`

```markdown
# 인계 노트 양식

파일명 `YYYY-MM-DD-NN-주제.md`. 보내는 쪽 폴더에 둔다.
받는 쪽은 읽은 뒤 `status`를 `확인`으로, `read:`에 날짜를 적는다. 그 외에는 고치지 않는다.

---
from: (보낸쪽)
to: (받는쪽)
date: YYYY-MM-DD
commit: abc1234     # 직전 커밋. 없으면 "미커밋"
status: 대기        # 받는 쪽이 읽으면 "확인"
read:               # 받는 쪽이 읽은 날짜
---

## 무엇을 했나
(두세 문단. 왜 그렇게 했는지도)

## 바뀐 파일
- 경로 — 무엇이 바뀌었나

## 상대에게 요청
- (없으면 "없음")

## 사용자 판단이 필요한 것
- (없으면 "없음")

작성 원칙: 결과만이 아니라 판단 근거를 적는다. 상대 담당 {{산출물}}에 대한 의견은 "상대에게 요청"에 넣고 직접 고치지 않는다. 하지 않은 것도 적는다("{{금지행위}}는 하지 않았다"). 사용자 판단이 필요한 항목은 도구끼리 결정하지 않고 남긴다.
```
