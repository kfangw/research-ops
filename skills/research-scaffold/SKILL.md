# 연구 프로젝트 스캐폴드

논문 한 편이나 연구 하나를 저장소 하나로 관리하는 폴더 구조를 만든다. 원고, 기록, 코드, 자료, 결과를 한 저장소에 두고, 공개할 산출물이 있으면 공개 저장소를 따로 둔다. 만든 뒤의 세션 절차와 공통 규칙은 research-session을 따른다.

## 1. 틀의 정본

틀은 운영 체계 저장소(이 스킬이 들어 있던 저장소)의 `scaffold/`(`new-project.sh`와 `template/`)다. 사용자 컴퓨터에 그 저장소의 클론이 있으면 거기서 쓴다. 없으면 사용자에게 저장소 주소를 받아 클론한다. 명령은 그 저장소 루트에서 `scaffold/new-project.sh`로 부른다. 이 스킬에는 틀을 복사해 두지 않는다. 사본은 정본과 어긋나기 때문이다.

## 2. 값 정하기

| 값 | 뜻 | 기본값 |
|---|---|---|
| 폴더 경로 | 만들 곳 | 없음 |
| 프로젝트 이름 | 저장소 이름. 영문 소문자, 숫자, `.`, `_`, `-`만 | 폴더 이름 |
| 사용자 이름 | 문서와 투고용 artifact의 금지어에 들어간다. `SCAFFOLD_USER`로 준다 | `git config user.name`. 도구 이름(예: claude)이면 사용자에게 묻는다 |
| 한 줄 설명 | 무엇을 하는 폴더인가 | 없음 |
| 산출물 단위 | 담당을 나누는 단위 | 원고 |
| 금지 행위 | 사용자 확인 없이 하면 안 되는 일 | 실험 실행 |
| 도구 | 쓰는 도구, 하나나 둘. `SCAFFOLD_TOOLS`로 준다(예: `claude`, `codex`, `claude,codex`) | `claude,chatgpt` |
| 공개 저장소 | 공개할 산출물이 있나 | 없음 |

대화에서 정해지지 않은 값만 묻는다. 기본값을 쓰면 그렇게 했다고 말한다.

## 3. 만들기

1. `scaffold/new-project.sh <폴더> <이름> "<설명>" "<산출물 단위>" "<금지 행위>"`. 이미 있는 폴더면 끝에 `--existing`을 붙인다. 기존 파일은 덮지 않고, 겹치는 파일(`AGENTS.md`, `CLAUDE.md`, `README.md`, `.gitignore`)은 `.scaffold`를 붙여 둔다.
2. 에이전트가 돌릴 때는 `SCAFFOLD_PUSH=n`, 사용자 이름은 `SCAFFOLD_USER="<이름>"`, 도구는 `SCAFFOLD_TOOLS="<도구>[,<도구>]"`로 준다. 원격 저장소 생성과 push는 사용자 확인 뒤에 한다.
3. 프로젝트 설정(`docs/설정.md`)을 채운다. 도구 목록, 역할별 모델, 원고(언어, 투고처, 쪽 상한, 마감, 익명), 지킬 것(금지 행위, 자료 원칙). 여러 편을 함께 다루면 포트폴리오 폴더 경로와 공용 문헌 대장 경로도 적는다.
4. 도구가 하나면 인계 노트 폴더와 양식을 넣지 않고 세션 기록만 쓰는 틀이 만들어진다. 도구 이름은 커밋 접두, 세션 기록 파일 이름, 설정의 도구 표에 들어간다.
5. 공개 저장소를 둘 경우: 비공개 저장소 안에 공개 저장소를 하위 폴더로 두고 비공개 저장소의 `.gitignore`에서 뺀다. 공개 저장소에는 금지어 검사(운영 체계 저장소의 `code/scripts/check-banned.sh`)를 push 전 훅으로 건다. 거는 법은 그 스크립트 머리에 있다. 금지어 목록은 비공개 저장소에만 둔다.

## 4. 뒤처리

1. `.scaffold` 파일을 기존 파일과 손으로 합치고 지운다. 기존 내용을 버리지 않는다.
2. 만든 뒤에 도구를 더하거나 바꾸면 `docs/설정.md`의 도구 표, `AGENTS.md`, `00-교류/`의 인계 노트 폴더(`<보낸 도구>-to-<받는 도구>/`)를 함께 고친다. 하나에서 둘로 늘리면 운영 체계 저장소의 `scaffold/template/00-교류/`에서 인계노트-양식과 폴더를 가져온다.
3. 현황의 산출물 표, 승인기록, 할일목록, 연구계획을 대화에서 정한 내용으로 채운다. 사용자 결정과 도구 권고를 구별한다.
4. `--existing`이면 첫 세션 기록과 첫 인계 노트를 실제로 한 일에 맞게 고친다.
5. 스크립트가 넣은 파일에 `{{`가 남았는지 본다. 기존 파일의 자리표시자는 일부러 둔 것일 수 있으니 건드리지 않는다.
6. 연결 폴더에서 git 커밋이 잠금 파일에서 멈추면 research-session 7절을 따른다.
7. 사용자에게 남은 명령(첫 커밋, 원격 저장소 생성)을 보이고, 만든 폴더의 `README.md`를 답에서 바로 열 수 있게 보인다.

## 5. 하지 않을 것

- 기존 파일에 자리표시자 치환을 하지 않는다.
- 처음 만들 때 원격 저장소 생성과 첫 push는 사용자 확인 뒤에 한다. 그 뒤의 push는 research-session 3절을 따른다.
- 틀을 이 스킬 안에 복사해 두지 않는다.
