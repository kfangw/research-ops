# 논문 할 일 목록 갱신

"할 일 목록 업데이트", "배치 갱신", "에이전트에 매핑" 같은 요청에 쓴다. 대상은 `<프로젝트 루트>` 폴더(컴퓨터)와 claude.ai 프로젝트 "논문"이다. 컴퓨터 폴더가 정본이고 프로젝트 문서는 사본이다.

## 1. 현재 상태 읽기 (정본 먼저)

1. `HANDOFF/STATE.md` 맨 위 3~5항목, `HANDOFF/LOG.md` 마지막 5줄, `git log --oneline -10`, `git status --short`.
2. 현행 원고 폴더(`<원고 폴더>/<현행>/manuscript_v*`)의 최신 판과 `<계획 폴더>/할일목록_v*` 최신 판.
3. claude.ai 프로젝트 색인(`claude/README_프로젝트_색인.md`)이 정본보다 늦은지 확인한다. 늦으면 사용자에게 한 줄로 알린다.
4. STATE의 시각이 실제 파일 수정 시각과 어긋나면 오기로 적어 둔다.

## 2. 내용 정하기

- 사용자 결정은 시각과 함께 그대로 적는다. 추측으로 결정을 채우지 않는다.
- 약점이나 목표가 있으면 표로: 번호(W1…), 약점, 목표(완전/상당/부분 해소), 해당 배치.
- 배치 표 열: 배치 | 담당 | 내용 | 산출(파일 경로) | 선행 | 예정(날짜) | 상태.
- 순서를 한 줄로 적는다(병행은 ∥).
- 사용자 작업 표: 작업, 걸리는 시간, 기한, 비고. 기한이 걸린 것은 굵게.
- 남은 사용자 결정 표: 결정, 권고, 언제.
- 위험 표: 위험, 가능성, 생기면 할 일. 결과 방향이 불리할 때의 서술을 미리 적는다.
- 원칙: 새 규칙은 집계 전 해시 고정, 결과 방향과 무관하게 보고, 저자(에이전트 포함)가 정한 것은 공개.

## 3. 에이전트·모델 매핑 (사용자가 따로 정하지 않으면 기본값)

| 역할 | 모델 | 맡는 일 |
|---|---|---|
| 총괄 | Fable | 관문(F1…) 판단, 해시 고정 확인, 산출 수락·반려, 사용자 보고, STATE·LOG·HANDOFF |
| 규칙·원고 | Opus | 규칙 문서, 판정 지침, 원고 재편, 윤문, 대응표 |
| 집계·코드 | Sonnet | 양식, 집계 스크립트, 빌드, bundle |
| 독립 검산 | 별도 Sonnet | 규칙 문서와 원자료만 받아 재계산, 숫자 대조 |
| 새 독자 | 별도 Sonnet | 비전문가로 읽고 막히는 곳만 표시 |
| 심사 | Opus ×3 | 익명본만 받고 이전 심사평 비공개 |

규칙: 만든 에이전트는 자기 산출을 채점하지 않는다. 검산·심사 에이전트는 새로 띄우고 앞선 대화를 넘기지 않는다. 규칙을 쓰는 에이전트는 결과 JSON을 보지 않는다. 결과를 보고 주장을 바꾸는 판단은 총괄 관문에서만 한다.

## 4. 파일 쓰기

1. 새 판본 파일을 만든다: `01_계획/할일목록_v<번호>_<YYYY-MM-DD>.md`. 이전 판은 덮어쓰거나 지우지 않는다. 첫 줄에 "— 할일목록_v<이전>을 대체"와 총괄을 적는다.
2. `HANDOFF/claude_project_docs/`에 사본을 둔다.
3. `STATE.md` 맨 위 머리 시각을 고치고 새 항목 하나를 맨 위에 넣는다(바뀐 것, 사용자 결정, 문서 경로). python으로 제자리 수정한다.
4. `LOG.md` 맨 아래에 한 줄.
5. 사용자 결정이 새로 있으면 `HANDOFF/claude_to_chatgpt/<YYYY-MM-DD>_<주제>.md`를 HANDOFF README의 틀(한 것, 확인한 사실, 결정, 부탁, 다음 할 일)로 남긴다.
6. `git add -A && git commit -m "Claude: <요약>"`. 뒤에 `.git/*.lock`이나 `tmp_obj_*`가 남아 unlink 경고가 나면 폴더 삭제 권한을 한 번 요청해 지운다.

## 5. claude.ai 프로젝트 문서 맞추기

1. 새 목록을 컴퓨터에서 stage해 작업 디렉터리로 복사한 뒤 `project_write`로 `claude/할일목록_v<번호>_<날짜>.md`에 올린다(local_path는 작업 디렉터리 안이어야 함).
2. 대체된 이전 목록은 프로젝트에서 `project_delete`(컴퓨터에는 남아 있음).
3. 색인의 1절(지금 하는 일)·2절(다음 할 일 표)·3절(문서 표)을 새 판 기준으로 고쳐 다시 쓰고, 같은 파일을 `HANDOFF/claude_project_docs/`에도 commit_files로 둔다. 다시 커밋.

## 6. 답하기

- 한국어, 짧고 쉬운 문장. 무엇이 바뀌었는지, 역할·모델 표, 기한 걸린 사용자 작업, 커밋 해시.
- 새로 만든 파일마다 computer:// 링크를 같은 답에 붙인다.
- 실행은 사용자가 지시할 때만 시작한다. 목록 갱신과 실행을 섞지 않는다.
