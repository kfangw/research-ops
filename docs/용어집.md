# 용어집

스킬과 문서에서 같은 것은 같은 이름으로 부른다. 이 표의 "쓴다" 열만 쓰고, "쓰지 않는다" 열의 말은 고친다. 지난 기록(세션 기록, 인계 노트, 승인기록의 지난 줄)은 고치지 않는다.

## 1. 사람, 도구, 역할

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| 사용자 | 저자(사용자를 뜻할 때), 사람, 유저 | 연구를 하고 결정하는 사람. 논문의 저자를 뜻할 때만 "저자" |
| 도구 | AI(도구를 뜻할 때), 어시스턴트 | Claude, ChatGPT(Codex)처럼 사용자가 쓰는 AI 작업 도구 하나 |
| 에이전트 | 서브에이전트, 하위 에이전트, 워커 | 한 도구가 일을 맡기려고 띄우는 작업 단위 |
| 총괄 | 오케스트레이터, 메인 에이전트, 편집자(역할 이름으로) | 순서, 판정, 재계산, 보고, 기록을 맡는 역할 |
| 실행 | 워커, 작업자 | 스크립트, 집계, 수집, 조판, 원고 수정 |
| 규칙 작성 | 규칙 담당 | 판정 규칙과 사전 등록 문서를 쓰는 역할 |
| 독립 검산 (둘째부터 "검산") | 검증, 재검증, 교차 검증, verifier | 규칙 문서와 원자료만 받아 다시 계산 |
| 심사 | 리뷰, 리뷰어, referee, 모의심사(역할 이름으로) | 익명 원고와 심사 기준만 받아 지적. 행위는 "모의 심사"도 쓴다 |
| 새 독자 | 일반 독자, 비전문가 리뷰 | 배경 지식 없이 읽고 막힌 곳만 표시 |
| 문헌 정찰 | 문헌 조사 에이전트, 서베이어 | literature-scout의 갈래를 맡는 역할 |
| 반론자 | 상대 도구, 두 번째 의견 | 다른 계열 도구나 모델이 맡는 반박 역할 |
| 큰 모델, 중간 모델 | Fable, Opus, Sonnet(역할을 정할 때) | 모델 등급. 실제 모델 이름은 프로젝트 설정에만 적는다 |

## 2. 기록과 파일

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| 현황 (`00-교류/현황.md`) | STATE, 진행상태, 현황판(프로젝트 안) | 무엇이 현행이고 누가 맡는지. 단일 기준 |
| 세션 기록 (`00-교류/log/`) | LOG, 로그, 세션 대장 | 세션마다 파일 하나 |
| 인계 노트 | handoff, HANDOFF, 인계 파일 | 한 도구가 다른 도구에게 남기는 노트 |
| 승인기록 (`docs/승인기록.md`) | 결정기록, 결정 로그 | 사용자 결정과 세션 판정 |
| 할일목록 (`docs/할일목록.md`) | todo, 작업계획서(목록을 뜻할 때) | 배치와 항목 |
| 프로젝트 설정 (`docs/설정.md`) | config, 설정 파일 | 도구, 역할과 모델, 원고, 지킬 것 |
| 연구 지도 | research map, 연구지도(붙여 쓰기) | 여러 편의 위치와 경계를 한 장에 둔 문서 |
| 현황판 | 대시보드 | 여러 프로젝트를 묶은 일일 점검 결과(research-portfolio). 한 프로젝트 안에서는 현황 |
| 변경 기록 | revision log, 이동 기록표 | 원고 수정의 위치와 이유. 옮긴 문장을 포함 |
| 공용 문헌 대장 | 공유 문헌 목록, 문헌 원장 | 프로젝트 사이에 나누는 선행 연구 판정 |
| 어림 기록부 (`docs/어림기록.md`) | 확률 기록, 추정 로그 | 가능성 어림의 값과 고친 이유 |
| 숫자 대장 | numbers 파일, 수치 원장 | 원고의 숫자와 그 원천을 잇는 표 |
| 판 | 판본, 버전, version, 개정판 | 문서의 차례. 살아 있는 문서(현황, 할일목록, 승인기록, 설정)는 파일 이름을 고정하고, 지난 판을 `구판/`으로 내릴 때 `v<번호>`를 붙인다. 판으로 내는 문서(문제 정의, 연구 지도, 원고, 사양)는 파일 이름에 `v<번호>`를 붙인다 |
| 구판 (`구판/`) | old, 이전판 폴더, archive | 지난 판을 내리는 폴더 |

## 3. 연구 절차

| 쓴다 | 쓰지 않는다 | 뜻 |
|---|---|---|
| 문제 정의 | 문제정의(붙여 쓰기), problem statement | problem-grill의 산출물 |
| 틀 | 프레임, 프레이밍, framing | 문제 정의의 축 1, 5, 6, 7(문제, 논문의 종류, 주장, 정의상 참 점검) |
| 틀 변경 | 재정의, 리프레이밍, 피벗 | 잠근 뒤 틀의 축을 바꾸는 것 |
| 잠금 | 확정(판을 뜻할 때), 동결(원고가 아닌 문서) | 사용자가 승인한 판을 해시와 함께 고정 |
| 관문 | gate, 게이트(연구 판정을 뜻할 때) | feasibility-gate의 G0~G7 |
| 통과, 미통과, 조건부, 유보 | pass, fail, 부분 통과, 보류 | 관문 판정 |
| 문자 판정, 종합 판정 | 기계 판정, 실질 판정 | 기준을 글자 그대로 적용한 결과와 판정자의 종합 |
| 사전 등록 | 사전등록(붙여 쓰기), preregistration | 결과 전에 사양과 판정 규칙을 적는 일 |
| 봉인 | 해시 고정, sealing | 사전 등록 파일의 해시와 시각을 기록 |
| 이탈 | 위반, deviation | 봉인한 사양과 다르게 한 것 |
| 가능성 어림 | 확률 추정, 채택 가능성 | 어림이라고 밝힌 값 |
| 거리 1~4 | 근접도, 유사도 | 선행 연구와의 거리 |
| 확인 수준: 본문 확인, 초록만 확인, 열지 못함 | VERIFIED-FULL-TEXT, ABSTRACT-ONLY, NOT FOUND, 미확인 | 문헌을 어디까지 읽었나 |
| 배치, 항목 | 단계(배치를 뜻할 때), 태스크 | 실행 계획의 단위 |
| 진척률 | 진행률, 진도 | 항목 수로 센 비율. 12칸 막대로 보인다 |
| 시작 안내, 진행판, 마침 보고 | 브리핑, 대시보드, 상태 보고, 최종 보고 | 모든 스킬이 쓰는 세 보고 틀(research-session 8절). 진행판은 작업 중에, 현황판은 여러 프로젝트의 일일 점검에 쓴다 |
| 상태어: 예정, 진행, 대기, 막힘, 멈춤, 완료, 건너뜀 | 진행 중, 하는 중, 끝냄, 대기 중, 보류, 실패(상태로) | 항목과 에이전트의 상태. 대괄호로 적는다 |
| 마지막 신호 | 하트비트, 생존 신호 | 에이전트나 항목이 마지막으로 진척을 남긴 시각 |
| 대리 판정 | 임시 판정, 자체 판정 | 총괄이 사용자 대신 내린 판정. 사후 확인을 받는다 |
| 맡긴 작업, 맡김 | 야간 작업, 무인 실행, 자동 실행 | 사용자가 자리를 비운 동안 승인된 지시서대로 에이전트가 하는 일 |
| 맡김 지시서 | 야간 지시서, 작업 명세 | 떠나기 전에 쓰고 사용자가 승인하는 문서(`docs/맡김/<시작>-지시서.md`) |
| 검토서 | 아침 보고서, 결과 보고서 | 맡긴 작업의 결과. 사용자가 돌아와서 받음, 돌려보냄, 버림을 표시한다 |
| 검토 예산, 검토 대기 | 리뷰 시간, 백로그 | 사용자가 검토에 쓸 시간과, 아직 받지도 돌려보내지도 않은 항목 |
| 바퀴 (R1, R2) | 라운드, 회차, 사이클 | 품질 반복의 한 차례 |
| 큰 지적, 작은 지적 | 1급, 2급, major/minor(지적의 크기로) | 심사 지적의 크기 |
| 사실 대조 | 기계 대조, 팩트체크, 사실 보존 검산 | 고친 원고와 고정판의 숫자, 인용, 부등호, 헤지 비교 |
| 원고 | 페이퍼, 논문 파일 | 투고할 글 |
| 투고처 | venue, 학회지(일반적으로) | 학회나 저널 |
| 투고 묶음, 동결 | 제출 패키지, 프리즈 | 투고 직전에 고정한 판과 함께 내는 파일 전부(submission-package). 동결은 원고에만 쓴다 |
| 심사 대응 | rebuttal, 답변서, 반박문 | 실제 심사평에 답하는 일과 그 문서 |
| 답신 | response letter, 회신문 | 심사 대응 때 투고처에 보내는 글 |
| 공개 저장소, 비공개 저장소 | public repo, private repo | 공개할 산출물과 작업 기록을 나눠 두는 저장소 쌍 |

## 4. 기호와 표기

- 산문 문장 안에 가운뎃점(·), 줄표(—, –), 화살표(→), ≈, ≠를 쓰지 않는다. 셋 이상 나열은 쉼표로, 둘은 "과/와", "이나"로 잇는다.
- 표 칸, 코드 블록, 파일 이름, 식에서는 기호를 써도 된다. 코드 블록 안의 보고 예시(`이전 → 지금`)도 그대로 둔다.
- 범위는 물결표로 쓴다(40~50%, G0~G7, v4~v17).
- 강조용 굵은 글씨와 따옴표를 거의 쓰지 않는다. 표 머리와 정의되는 용어의 첫 등장만 예외로 한다.
- 절은 "1절", "2절"로 부른다. 스킬 이름, 파일 경로, 식별자는 영문 그대로 백틱으로 감싼다.
- 문장 끝은 "~다"로 쓴다(스킬과 문서). 대화 답변은 사용자 선호를 따른다.
