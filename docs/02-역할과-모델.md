# 02. 역할과 모델

역할이 기준이고 모델은 바뀐다. 2026년 10월 기준의 배정을 적되, 모델 이름은 예시다.

## 역할

| 역할 | 맡는 일 | 받지 않는 것 | 2026-10 배정(예) |
|---|---|---|---|
| 총괄 | 배치 순서와 착수 승인, 관문 판정, 에이전트가 낸 숫자의 재계산, 문서 간 정합성, 사용자 보고, 승인기록, 국문 문서 | 실행 세부 | 가장 큰 모델 하나 |
| 설계·증명·규칙 | 설계 문서, 증명, 사전 등록 규칙, 해석, 영문 원고, 심사 | 결과 파일(규칙을 쓸 때) | 큰 모델 |
| 실행 | 스크립트, 표, 집계, 수집, 조판, 빌드 | 자기 산출의 채점 | 중간 모델, 병렬 |
| 독립 검산 | 규칙 문서와 원자료만 받아 재계산 | 앞선 대화, 집계 코드 | 별도로 띄운 중간 모델 |
| 심사 | 익명 원고와 심사 기준만 받고 지적 | 이전 심사평 | 큰 모델 2~3개, 마지막 바퀴는 다른 계열 하나 |
| 새 독자 | 비전문가로 읽고 막힌 곳만 | 배경 지식 | 중간 모델 |
| 문헌 정찰 | 검색어를 명시하고 편 수와 핵심 논문을 보고 | 결론 | 중간 모델, 병렬 |

## 지킬 것

- 한 에이전트는 한 관심사만 맡는다. 서로 의존하지 않는 항목은 한 번에 함께 띄운다.
- 실행 모델이 일이 크다며 멈추면 큰 모델로 넘기고 쪼갠다.
- 에이전트 지시문에 늘 넣는 것: 역할과 파일 위치, 읽을 파일 목록, 보고할 숫자의 정확한 지정, "지시와 데이터가 다르면 데이터를 따르고 차이를 보고", 공개 저장소 규칙(커밋에 AI 흔적 없음).
- 문헌 정찰 에이전트에게는 "찾지 못함은 유효한 답이다. 논문을 지어내지 않는다"를 반드시 넣는다. 그리고 보고에 검색어를 그대로 적게 한다. 검색어가 없으면 "찾지 못함"을 검증할 수 없다.
- 에이전트가 낸 숫자는 총괄이 다시 계산한 뒤에 문서에 넣는다.

## 다른 계열 모델

마지막 심사 바퀴에는 다른 계열 모델(예: Codex)의 심사를 하나 넣는다. 같은 계열은 놓치는 곳이 겹친다. 다른 계열 도구가 같은 저장소를 쓰면 `docs/06-교류규약.md`를 따른다.
