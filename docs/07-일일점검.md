# 07. 일일 점검

여러 프로젝트를 동시에 진행하면 하루 한 번 전체 폴더를 읽는 점검을 둔다. 읽기만 하고 결정하지 않는다. 산출물은 여러 프로젝트를 한 장에 모은 현황판 하나(md)와 보기용 대시보드 하나다. 이 점검은 `research-portfolio` 스킬이 맡는다.

프롬프트 본문은 `templates/일일점검-프롬프트.md`에 있고, 아래는 설계 원칙이다.

## 원칙

- 읽기만 한다. 각 프로젝트 폴더의 파일은 고치지 않는다.
- 결정하지 않는다. 결정이 필요한 것은 `[멈춤]`(결정 필요)로 표시하고 선택지와 비용을 적는다.
- 모든 주장에 근거 파일과 수정 시각을 단다. 파일에 없는 진행은 적지 않는다.
- 파일이 바뀐 것과 진행이 있는 것은 다르다. 바뀐 파일을 읽고 무엇이 달라졌는지 확인한 뒤에만 진행으로 적는다. 파일 수는 진행량이 아니다.
- 어제와 같으면 같다고 쓴다.

## 읽는 순서

1. 지난 24시간 안에 수정된 파일. 문서와 자료, 코드를 나눠 센다. 같은 분에 20건 넘게 찍힌 묶음은 일괄 복사로 보고 변화로 세지 않는다.
2. 각 프로젝트의 결정과 판정 기록(승인기록, 현황, 세션 기록). 원고나 코드가 바뀌었는데 기록이 2시간 넘게 오래됐으면 "기록 지연"으로 표시한다.
3. 어제 현황판. 오늘의 "달라진 것 / 그대로인 것"은 이것과 비교한다.
4. 프로젝트별 기준 문서. 표에 적힌 위치에 없으면 "못 찾음"으로 적고 추측하지 않는다.

## 찾는 것

프로젝트 안에서는 단계, 24시간 변화, 다음 관문과 날짜, 막힘(외부 대기, 자원 만료, 결정 대기와 대기 시작 시각), 7일 이상 정체를 찾는다.

프로젝트 사이에서는 전달해야 할 정보(A의 결정 시각이 B의 최신 문서 시각보다 뒤이면 반영 전), 문서 간 어긋남, 14일 창의 마감 충돌, 공유 자원 충돌, 중복 작업을 찾는다.

## 공유 자원 원장

외부 API 크레딧, 모델 사용량 창, 지도교수 시간, 변리사 같은 자원을 원장으로 두고 매일 수치를 갱신한다. 폴더마다 수치가 다르면 어긋남으로 적는다.

## 현황판 구성

1. 오늘 봐야 할 것(최대 5줄) 2. 한눈에 보기 표 3. 프로젝트 사이 전달표 4. 문서 간 어긋남 5. 30일 타임라인 6. 어제와 달라진 것 7. 결정 대기 목록 8. 기록 지연 9. 프롬프트 수정점.

## 예약

사용자의 컴퓨터가 필요하면(폴더 읽기) 예약 작업에 그 컴퓨터를 붙인다. 시각은 아침으로 잡는다. 밤사이 맡긴 작업의 검토서(`away/` 브랜치)가 나와 있고, 하루 계획을 세우기 전에 읽을 수 있기 때문이다(`docs/08-사용자가-없는-시간.md`). 읽기와 한 폴더 쓰기만 하므로 자동 승인이 맞다.
