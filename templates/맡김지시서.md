# 맡김 지시서: <프로젝트> <YYYY-MM-DD-HHMM>

사용자가 자리를 비운 동안 에이전트가 할 일. 이 지시서는 main에, 결과와 검토서는 `away/<시작>` 브랜치에 둔다. `<시작>`은 이 지시서를 쓴 시각이다. 원칙은 `docs/08-사용자가-없는-시간.md`, 절차는 `research-batch` 8절.

작성: <총괄, 시각> / 사용자 승인: <시각. 비어 있으면 실행하지 않는다>
브랜치: `away/<YYYY-MM-DD-HHMM>` / 사용자가 돌아오는 시각: <시각> / 전체 마감: <돌아오기 1시간 전, 짧으면 15분 전>
검토 예산: <분> / 남은 검토 대기: <n>건
시작 방식: <지금 세션에서 이어서 | 예약 작업 (시각)> / 승인 설정: <자동 승인 | 승인이 필요한 동작 없음>

## 떠나기 전에 정한 것

- <결정, 승인기록의 날짜와 줄>

## 바꾸지 않을 것

| 무엇 | 판, 해시 | 위치 |
|---|---|---|
| 문제 정의 | v<n>, <해시> | `docs/문제정의-v<n>.md` |
| 주장 목록 | <날짜> | `<원고 폴더>/주장목록.md` |
| 봉인한 사양 | <해시> | `<경로>` |

여기에 닿는 발견은 고치지 않고 검토서의 결정 대기에 올린다.

아래 항목 표에 적고 승인받은 일은 프로젝트의 "사용자 확인 후에만 하는 일"(예: 실험 실행)이라도 확인을 받은 것으로 본다. 표에 없는 그런 일은 하지 않는다.

## 항목

| 번호 | 할 일 | 역할 | 산출(경로) | 통과 조건 | 확인 방법 | 시간 상한 | 우선순위 |
|---|---|---|---|---|---|---|---|
| W1 | | 실행 | | | 독립 검산 / 지시서에 적은 시험 / 확인 에이전트가 쓴 시험 / fact-check / 확인 수준 | | 1 |

순서: `W1 → W2 ∥ W3`

## 갈림길의 사전 결정

| 상황 | 할 일 |
|---|---|
| <예: 수집이 크레딧 상한의 80%에 닿음> | <표본을 절반으로 줄이고 계속, 검토서에 적음> |
| <예: 구현이 시험을 두 번 통과하지 못함> | <그 항목 멈춤, 실패 기록만 남기고 다음 항목> |
| 적지 않은 갈림길 | 되돌릴 수 있는 쪽을 고르고 대리 판정으로 적음. 되돌릴 수 없으면 그 항목 멈춤 |

## 멈춤 선

| 멈춤 선 | 값 | 닿으면 |
|---|---|---|
| 전체 마감 | <시각> | 진행 중인 항목 정리, 검토서 작성 |
| 같은 항목 실패 | 2회 | 그 항목 멈춤 |
| 크레딧, API 비용 | <상한> | 크레딧 쓰는 항목 모두 멈춤 |
| 확인 불일치 | 1건 | 그 결과에 기대는 항목 시작 안 함 |

## 하지 않을 것

- 제출, 공개 저장소 push, 메일과 메시지 발송
- 결과 파일과 원자료 삭제, 봉인한 사양 수정, 봉인하지 않은 실험 실행
- 문제 정의, 주장 목록, 관문 판정 수정
- 지시서에 없는 외부 서비스 가입, 결제, 설치
- `away/` 브랜치를 main에 합치기
- <프로젝트의 금지 행위>
