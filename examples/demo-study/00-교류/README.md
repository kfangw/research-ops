# 00-교류: 이 프로젝트의 세션 기록과 도구 사이의 교류

claude는 세션마다 이 폴더에 기록을 남기고, 다음 세션은 그 기록을 읽고 시작한다.
루트의 `AGENTS.md`(Codex가 읽음)와 `CLAUDE.md`(Claude가 읽음, AGENTS.md를 가리킴)는 이 문서를 가리킨다.

## 구성

| 파일, 폴더 | 무엇 | 누가 고치나 |
|---|---|---|
| `현황.md` | 무엇이 현행이고 다음에 무엇을 하는지. 단일 기준 | 세션 끝에 갱신 |
| `log/YYYY-MM-DD-NN-도구.md` | 세션 기록. 세션마다 파일 하나 | 쓴 쪽만 |

## 세션을 시작할 때

1. 원격(origin)이 있으면 `git pull --rebase origin main`.
2. `현황.md`를 읽는다.
3. `log/`의 최근 세 파일을 읽는다.
5. `git log --oneline -20`.

## 세션을 마칠 때

2. `현황.md` 갱신. 현행 판이 바뀌었으면 반드시.
3. `log/`에 세션 파일 하나. 양식은 `log/README.md`.
4. 도구 이름을 접두로 붙여 커밋한다(예: `[claude]`). 몰아서 하지 않고 작업 단위마다 한다.
5. `git push origin main`. 거절되면 pull --rebase 후 다시.

## 충돌을 피하는 규칙

- 현행 판의 위치는 `현황.md`에만 적는다. 다른 문서가 어긋나면 `현황.md`가 맞다.
- 새 판은 올리고 지난 판은 `구판/`으로 내린다. 지우지 않는다.
- 사용자 확인 후에만 하는 일: 실험 실행. 그 직전 단계까지 준비하고 세션 기록에 적는다.

## git 규칙

- 저장소는 프로젝트 루트. 원격은 GitHub private `origin/main`. 기준선 커밋 `첫 커밋 (git rev-list --max-parents=0 HEAD)`.
- 브랜치는 `main` 하나. 긴 실험처럼 며칠 걸리는 일만 `exp/이름` 브랜치를 쓰고 끝나면 합친다. 사용자가 자리를 비운 동안 맡긴 작업은 `away/<시작>` 브랜치에 두고, 사용자가 받은 항목만 검토 뒤 main에 합친다.
- 20MB 넘는 원자료와 원결과는 폴더에 두되 git에는 넣지 않는다.
- 이력을 고쳐 쓰지 않는다(`rebase -i`, `push --force` 금지). 잘못 커밋했으면 되돌리는 커밋을 새로 만든다.
- 작업 환경이 파일을 못 지워 git이 `index.lock`이나 `objects/*/tmp_obj_*`에 걸리면 사용자에게 삭제 권한을 요청한 뒤 지우고 다시 한다.
- 커밋의 작성자는 사용자이고 도구는 공동 작성자다. 도구가 만든 커밋은 접두(`[claude]`)를 붙이고 메시지 끝에 `docs/설정.md`의 공동 작성자 줄을 붙인다.
- 도구별 커밋은 `git log --grep='^\[claude\]'`로 거른다.
