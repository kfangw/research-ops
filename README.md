[English summary](README.en.md)

LLM 에이전트에게 연구 작업을 나눠 맡길 때, 에이전트가 낸 숫자와 판정을 믿고 쓸 수 있게 하는 절차, 양식, 스킬, 프로젝트 틀이다. Claude Code와 Codex에서 쓰며, 저장소 주소만 건네면 AI 도구가 스스로 읽고 안내한다. 연구 내용은 담지 않고 절차만 담는다.

## 한눈에

사용자는 정하고 검토한다. 에이전트는 조사하고, 구현하고, 서로를 확인한다.

```
  사용자 (낮)                                   에이전트 (밤, 회의, 주말)

  문제 정의를 잠근다        --+
  판정 기준을 봉인한다        +-- 맡김 지시서 -->  조사, 구현, 집계
  맡길 일과 멈춤 선을 정한다 --+                         |
                                                         v
                                                  다른 에이전트가 검산
                                                  (만든 쪽은 채점하지 않는다)
                                                         |
  받을 것만 main에 합친다   <-- 검토서 ----------  정하지 못한 갈림길은
  남은 결정에 답한다                              고르지 않고 결정 대기로
```

사용자가 자리를 비운 동안(밤, 회의, 주말)에도 에이전트가 일할 수 있다. 세션을 마칠 때 맡김 지시서(바꾸지 않을 것, 갈림길의 사전 결정, 멈춤 선, 검토 예산)를 승인하면 에이전트는 `away/` 브랜치에서 일하고, 다른 에이전트가 결과를 확인해 검토서로 정리한다. 맡기는 양은 에이전트의 능력이 아니라 사용자의 검토 시간으로 정한다. (`docs/08-사용자가-없는-시간.md`, `research-batch` 8절)

에이전트는 다음 세 가지를 스스로 지키지 못하는 경우가 많고, 하나라도 무너지면 사용자가 결과를 처음부터 다시 봐야 한다. 이 저장소는 셋을 파일과 절차로 지킨다.

1. 결과를 본 뒤에 판정 기준을 바꾸지 않는다. 기준은 결과 전에 적고 해시로 봉인한다.
2. 결과를 만든 쪽이 채점하지 않는다. 검산과 심사는 앞선 대화를 받지 않은 새 에이전트가 한다.
3. 찾지 못한 것과 없는 것을 구별한다. 문헌 정찰은 쓴 검색어와 열지 못한 문헌까지 남긴다.

## 견본에서 일어난 일

`examples/demo-study`는 가상 주제로 일주일을 채운 견본 프로젝트다. 주제와 숫자는 지어냈지만, 기록은 절차를 그대로 따랐다.

- 신규성 관문(G0)에서 독립 검산 에이전트가 문헌마다 거리 판정을 다시 했고, 문헌 C에서 처음 판정과 갈렸다. 판정자가 다르면 더 가까운 쪽을 택한다는 규칙을 미리 적어 두었으므로 C를 3에서 2로 고쳤다. 열지 못한 문헌 하나는 판정하지 않고 조건으로 남겼다. (`docs/관문/2026-10-03-G0.md`)
- 밤사이 맡긴 일 3건(22:31~04:52)은 모두 끝났고 확인도 통과했다. 그 과정에서 에이전트는 봉인한 규칙에 중도 절단 자료를 중앙값에 넣는 방법이 없다는 것을 찾았다. 어느 쪽을 고르느냐에 따라 결과가 1.5일 달라졌으므로, 에이전트는 고르지 않고 결정 대기로 올렸다. 사용자는 아침에 18분(예산 30분) 동안 검토하며 답을 정했고, 수집 두 항목은 받고 깊이별 집계(W3)는 돌려보냈다. (`docs/맡김/2026-10-05-2230-검토서.md`)
- 세션 기록마다 시작 안내, 진행판, 마침 보고가 같은 모양으로 남아 있다. (`00-교류/log/`)

## 시작하기

AI 도구가 읽을 안내는 `AGENTS.md`에 있다(Claude Code는 `CLAUDE.md`를 거쳐 같은 파일을 읽는다). Claude Code나 Codex에 다음 가운데 하나를 그대로 붙여 넣으면 된다. `<주소>`는 이 저장소의 주소다.

처음 써 볼 때:

```
<주소> 를 클론하고 AGENTS.md를 읽어 줘. 그다음 내 연구에 어떻게 쓸 수 있는지 짧게 알려 주고, 지금 내 상황을 물어봐.
```

새 프로젝트를 바로 만들고 싶을 때:

```
<주소> 를 클론하고 AGENTS.md를 따라 ~/Projects/<이름> 에 연구 프로젝트를 만들어 줘. 정해야 할 값은 먼저 물어봐.
```

스킬만 설치하고 싶을 때:

```
<주소> 를 클론하고 AGENTS.md 4절대로 스킬을 설치해 줘. 어디에 넣을지 먼저 보여 줘.
```

이 저장소는 당분간 자주 바뀐다. 스킬을 설치해 두면 도구가 세션을 시작할 때 주기적으로(기본 7일) 새 판을 확인하고 알린다. 직접 확인하려면 `code/scripts/install-skills.sh check`, 갱신하려면 `update`를 돌린다. 사용자가 고친 스킬은 덮지 않는다. 판 번호는 `VERSION`, 바뀐 것은 `CHANGELOG.md`에 있다.

claude.ai처럼 저장소를 내려받지 못하는 곳에서는 `AGENTS.md`와 필요한 `skills/<이름>/SKILL.md`를 대화에 붙이거나, 스킬을 zip으로 올려 쓴다(`AGENTS.md` 4절).

### 처음 쓸 스킬

스킬 17개를 다 알 필요는 없다. 처음에는 착수 단계의 셋만 쓴다.

```
 1 problem-grill          2 literature-scout         3 feasibility-gate
 "문제 정리해 줘"   -->   "선행 연구 찾아"     -->   "해볼 만해?"
 한 문장 문제 정의와       가장 가까운 논문과         결과 전에 정한 기준으로
 반증 조건을 잠근다        거리, 찾지 못한 것의 기록   착수할지 접을지 판정
```

이 셋만 설치하려면 다음을 돌린다. 공통 규칙을 담은 `research-session`은 함께 들어간다.

```
ONLY=problem-grill,literature-scout,feasibility-gate code/scripts/install-skills.sh claude
```

채워진 예는 `examples/demo-study`의 1~3번 파일(문제 정의, 정찰, 관문)이다. 나머지는 필요할 때 더한다.

| 이럴 때 | 더할 스킬 |
|---|---|
| 프로젝트 폴더를 처음부터 갖추고 싶다 | `research-scaffold` |
| 실험이나 측정을 시작한다 | `preregister-seal` |
| 할 일이 여럿이고 에이전트에게 나눠 맡긴다, 자는 동안 돌리고 싶다 | `research-batch` |
| 숫자와 인용을 확인한다 | `fact-check` |
| 원고를 쓴다 | `paper-framing`, `paper-quality-loop` |
| 투고한다, 심사평을 받았다 | `submission-package`, `rebuttal` |
| 논문이 여러 편이다 | `research-portfolio` |

## 원칙

1. 판정 규칙은 결과를 보기 전에 파일로 적고, 해시를 기록해 봉인한다. 봉인 뒤 규칙을 바꾸려면 사용자가 정하고 이유를 남긴다. (`docs/04-사전등록과-봉인.md`, `code/scripts/seal.py`)
2. 검산은 집계한 에이전트가 아닌 다른 에이전트가 맡는다. 검산 에이전트는 규칙 문서와 원자료만 받고, 앞선 대화와 집계 코드는 받지 않는다. (`docs/05-독립검산.md`)
3. 새 주제, 새 설계, 새 주장은 통과 기준을 먼저 정한 관문(G0~G7)을 거친다. 기준을 넘지 못하면 접거나 범위를 줄인다. (`docs/03-관문.md`)
4. 진척과 가능성은 숫자로 보고한다. 어림은 어림이라고 밝히고, 고친 이력을 남긴다.
5. 제출, 공개 저장소 push, 원격 저장소 생성, 계정 설정, 되돌릴 수 없는 결정은 사용자가 한다. 에이전트는 그 직전 단계까지 준비한다.
6. 결정과 판정은 대화가 아니라 파일에 시각과 함께 남긴다. 다음 세션은 파일을 읽고 시작한다. (`docs/06-교류규약.md`, `scaffold/`)
7. 결과와 숫자는 숨기거나 바꾸지 않는다. 가설에 반하는 결과, 접은 주제, 틀린 어림도 기록에 남긴다. 다만 원고에서 약점을 필요 이상으로 고백하지 않고, 불리한 결과에는 범위를 깎기 전에 설계로 답할 방법을 먼저 찾는다.

원칙마다 필요한 이유와 지키는 방법은 `docs/01-원칙.md`에 있다.

## 진행 보이기

모든 스킬은 같은 틀로 진행을 보인다. 일을 시작하기 전에는 시작 안내, 상태가 바뀔 때는 진행판, 끝날 때는 마침 보고를 낸다. 상태는 일곱 낱말로만 적고, 사용자가 보는 곳에 5분 넘게 아무 표시도 없게 두지 않는다. 모양이 늘 같으므로 첫 줄과 왼쪽 칸만 보면 어디를 읽을지 안다.

```
== 진행 | demo-study | 선행 연구 정찰과 G0 판정 | 14:19 (시작 14:02, 경과 17분, 남은 어림 28분) ==
전체   [####--------] 2/5  40%
단계   1 검색어 [완료]  2 정찰 [진행]  3 거리 판정 [예정]  4 검산 [예정]  5 G0 [예정]

에이전트    역할        맡은 일              상태     시작   마지막 신호  진척
scout-a     문헌 정찰   학회 3곳, 2019~      [완료]   14:07  14:18        후보 41
scout-b     문헌 정찰   프리프린트           [진행]   14:07  14:19        34/80

대기   scout-b, 어림 6분, 14:25에 다시 알림
결정   없음
```

규범은 `research-session` 8절, 이유와 예시는 `docs/09-진행-보이기.md`, 양식은 `templates/진행판.md`에 있다.

## 스킬

스킬은 연구의 단계를 따라 나뉜다. 모든 스킬의 공통 규칙은 `research-session`에 한 번만 적고, 다른 스킬은 그 규칙을 가리킨다.

| 단계 | 스킬 | 하는 일 |
|---|---|---|
| 운영 기반 | `research-scaffold`, `research-session` | 프로젝트 만들기, 세션의 시작과 마침, 공통 규칙 |
| 여러 편 | `research-portfolio` | 연구 지도, 편 사이 경계, 공용 문헌 대장, 투고처와 요건, 일일 점검 |
| 착수 | `problem-grill`, `literature-scout`, `feasibility-gate` | 문제 정의와 잠금, 선행 연구 정찰, 관문 G0~G7 판정 |
| 실행 | `preregister-seal`, `research-batch` | 사전 등록과 봉인, 배치 계획과 실행과 보고, 자리를 비운 동안 맡기기 |
| 원고 | `paper-framing`, `paper-quality-loop`, `paper-readability`, `paper-condense` | 초록, 서론, 결론의 구조, 심사와 수정의 바퀴, 가독성, 분량 |
| 투고 | `submission-package` | 투고 판 동결, 일반본과 익명본, 재현 자료, 투고 화면 값, 마지막 점검 |
| 심사 뒤 | `rebuttal` | 실제 심사평의 지적 분류, 원고 수정, 대응표와 답신 |
| 공용 | `fact-check`, `korean-academic-style`, `english-academic-style` | 사실 대조, 국문과 영문 문체 |

## 역할

에이전트는 역할 단위로 띄우고, 역할마다 받지 않는 정보를 정해 둔다.

| 역할 | 하는 일 | 받지 않는 것 |
|---|---|---|
| 총괄 | 배치 순서, 관문 판정, 에이전트가 낸 수치의 재계산, 보고와 기록 | 실행 세부 |
| 실행 | 스크립트, 집계, 수집, 조판, 원고 수정 | 자기 산출의 채점 |
| 규칙 작성 | 판정 규칙, 사전 등록 문서 | 결과 파일 |
| 독립 검산 | 규칙 문서와 원자료만으로 다시 계산 | 앞선 대화, 집계 코드 |
| 심사 | 익명 원고와 심사 기준으로 지적 | 이전 심사평, 저자 의도 |
| 새 독자 | 비전문가 입장에서 막히는 곳 표시 | 배경 지식 |

역할별 모델 배정은 `docs/02-역할과-모델.md`에 있다. 모델은 자주 바뀌므로 역할을 기준으로 삼고, 모델은 큰 모델과 중간 모델의 등급으로만 적는다.

## 구성

| 경로 | 내용 |
|---|---|
| `AGENTS.md`, `CLAUDE.md` | 주소를 받은 AI 도구가 먼저 읽는 안내 |
| `skills/` | 스킬 17개. Claude Code, Codex, claude.ai에서 쓴다 |
| `scaffold/` | 새 연구 프로젝트를 만드는 `new-project.sh`와 그 틀(`template/`). 사용법은 `scaffold/README.md` |
| `templates/` | 사전 등록, 관문, 배치표, 맡김 지시서, 검토서, 진행판, 검산과 심사와 새 독자 지시문, 일일 점검 프롬프트 |
| `docs/` | 원칙과 절차 설명 9편, 용어집 |
| `examples/` | 채워진 견본 프로젝트 `demo-study`, 관문 판정과 독립 검토의 기록 예시 |
| `code/scripts/seal.py` | 판정 규칙 파일의 봉인과 검증 |
| `code/scripts/install-skills.sh` | 스킬 설치, 새 판 확인(`check`), 갱신(`update`), claude.ai용 zip |
| `code/scripts/check-banned.sh` | 공개 전 금지어 검사. push 전 훅으로 건다 |
| `code/scripts/selftest.sh` | 스크립트와 틀이 돌아가는지 점검. GitHub Actions가 push마다 돌린다 |

## 한계

- 한 사람이 자기 연구에 쓰면서 만든 절차다. 여러 사람이 한 저장소를 함께 쓰는 경우나 다른 연구 분야에서는 아직 시험하지 않았다.
- 교류 규약과 스킬은 Claude와 Codex를 함께 쓰는 환경을 기준으로 썼다.
- 독립 검산과 재계산에는 시간이 든다. 이 시간을 줄이면 절차가 보장하는 것도 함께 줄어든다.
- 문체 스킬 두 편(`korean-academic-style`, `english-academic-style`)은 한 연구자의 규범이다. 자기 규범으로 바꿔 쓰는 것을 전제로 둔다.
