# research-ops

LLM 에이전트 여럿에게 연구 작업을 나눠 맡길 때, 에이전트가 낸 수치와 판정을 사람이 검증할 수 있도록 만든 절차와 양식 모음이다. 판정 규칙의 사전 등록, 독립 검산, 단계별 관문, 도구 사이의 교류 규약을 문서와 스크립트, 스킬로 정리했고, 이 절차를 처음부터 갖춘 연구 프로젝트를 만드는 스캐폴드를 함께 둔다.

연구 내용은 담지 않는다. 절차만 담는다.

## 배경

에이전트는 작업을 빠르게 처리하지만, 결과를 믿고 쓰려면 다음 세 가지가 지켜져야 한다.

1. 결과를 본 뒤에 판정 규칙을 바꾸지 않는다.
2. 결과를 만든 쪽이 그 결과를 채점하지 않는다.
3. 찾지 못한 것과 존재하지 않는 것을 구별한다.

에이전트는 이 셋을 스스로 지키지 못하는 경우가 많다. 하나라도 무너지면 사람이 결과를 처음부터 다시 검토해야 하고, 에이전트를 쓴 시간 이득도 사라진다. 이 저장소는 세 조건을 개인의 주의가 아니라 절차와 파일로 지키게 한다.

## 원칙

1. 판정 규칙은 결과를 보기 전에 파일로 적고, 그 해시를 기록해 봉인한다. 봉인 뒤 규칙을 바꾸려면 사람이 결정하고 이유를 남긴다. (`docs/04-사전등록과-봉인.md`, `code/scripts/seal.py`)
2. 검산은 집계한 에이전트와 다른 에이전트가 맡는다. 검산 에이전트는 규칙 문서와 원자료만 받고, 앞선 대화와 집계 코드는 받지 않는다. (`docs/05-독립검산.md`)
3. 새 주제, 새 설계, 새 주장은 통과 기준을 먼저 정한 관문을 거친다. 기준을 넘지 못하면 접거나 범위를 줄인다. (`docs/03-관문.md`)
4. 진척과 가능성은 수치로 보고한다. 어림값은 어림이라고 밝히고, 고친 이력을 남긴다.
5. 제출, push, 계정 설정, 되돌릴 수 없는 결정은 사람만 한다. 에이전트는 그 직전 단계까지 준비한다.
6. 결정과 판정은 대화가 아니라 파일에 시각과 함께 남긴다. 다음 세션은 파일을 읽고 시작한다. (`docs/06-교류규약.md`, `scaffold/`)
7. 가설에 반하는 결과, 접은 주제, 틀린 어림도 기록에 남긴다.

원칙마다 필요한 이유와 지키는 방법은 `docs/01-원칙.md`에 있다.

## 구성

| 경로 | 내용 |
|---|---|
| `docs/` | 원칙과 절차 설명 7편 |
| `templates/` | 사전 등록, 관문, 배치표, 배치 보고, 검산·심사·새 독자 지시문, 일일 점검 프롬프트 |
| `scaffold/` | 새 연구 프로젝트를 만드는 `new-project.sh`와 그 틀(`template/`) |
| `skills/` | 절차를 Claude Code나 claude.ai 프로젝트에서 쓸 수 있게 만든 스킬 10개 |
| `code/scripts/seal.py` | 판정 규칙 파일의 봉인과 검증 |
| `examples/` | 관문 판정과 독립 검토의 기록 예시(익명 처리) |
| `protocols/구판/` | 스캐폴드 이전의 교류 규약. 비교용으로 둔다 |

## 역할

에이전트는 역할 단위로 띄우고, 역할마다 받지 않는 정보를 정해 둔다.

| 역할 | 하는 일 | 받지 않는 것 |
|---|---|---|
| 총괄 | 배치 순서, 관문 판정, 에이전트가 낸 수치의 재계산, 보고와 기록 | 실행 세부 |
| 실행 | 스크립트, 집계, 수집, 조판, 원고 수정 | 자기 산출의 채점 |
| 규칙 작성 | 판정 규칙, 사전 등록 문서 | 결과 파일 |
| 독립 검산 | 규칙 문서와 원자료만으로 다시 계산 | 앞선 대화, 집계 코드 |
| 심사 | 익명 원고와 심사 기준으로 지적 | 이전 심사평, 저자 의도 |
| 새 독자 | 비전문가 입장에서 막히는 곳 표시 | 배경 지식 |

역할별 모델 배정 예는 `docs/02-역할과-모델.md`에 있다. 모델은 자주 바뀌므로 역할을 기준으로 삼는다.

## 시작하기

1. 스캐폴드로 프로젝트 폴더를 만든다. 이미 있는 폴더에는 `--existing`을 붙이며, 기존 파일은 덮어쓰지 않는다. 자세한 사용법은 `scaffold/README.md`에 있다.
   ```
   scaffold/new-project.sh ~/Projects/my-study my-study "한 줄 설명"
   ```
2. 남은 작업을 배치로 나눠 새 프로젝트의 `docs/할일목록.md`에 적는다. 항목마다 역할, 통과 조건, 선행 조건, 어림 시간을 둔다. 양식은 `templates/배치표.md`.
3. 실험이나 측정 전에 `templates/사전등록.md`로 판정 규칙을 적고 `code/scripts/seal.py`로 봉인한다.
4. 결과가 나오면 새 에이전트에게 `templates/검산지시문.md`로 다시 계산하게 하고, 총괄이 두 결과를 대조한다.
5. `templates/관문.md`로 관문 통과 여부를 판정하고 `docs/승인기록.md`에 남긴다.
6. 원고는 `skills/paper-quality-loop`의 심사와 수정 주기로 다듬는다.

## 한계

- 한 사람이 자기 연구에 쓰면서 만든 절차다. 여러 사람이 한 저장소를 함께 쓰는 경우나 다른 연구 분야에서는 아직 시험하지 않았다.
- 교류 규약과 스킬은 Claude와 Codex를 함께 쓰는 환경을 기준으로 썼다.
- 독립 검산과 재계산에는 시간이 든다. 이 시간을 줄이면 절차가 보장하는 것도 함께 줄어든다.
- 문체 스킬 두 편(`korean-academic-style`, `english-academic-style`)은 특정 저자의 규범이다. 자기 규범으로 바꿔 쓰는 것을 전제로 둔다.
