**AI 에이전트에게 연구를 맡겨도 그 결과를 믿고 쓸 수 있게 해 주는 스킬과 절차입니다.** Claude Code와 Codex에서 씁니다.

[English summary](README.en.md)

## 에이전트에게 연구를 맡기면 생기는 일

에이전트는 빠릅니다. 그런데 그대로 두면 이런 일이 생깁니다.

| 에이전트가 하는 일 | 이 저장소가 하는 일 |
|---|---|
| 결과를 보고 나서 판정 기준을 슬쩍 바꾼다 | 기준을 결과 전에 파일로 적고 해시로 봉인한다. 한 글자만 바꿔도 드러난다 |
| 자기가 낸 숫자를 자기가 확인하고 "맞다"고 한다 | 앞선 대화를 모르는 새 에이전트가 원자료만 받아 다시 계산한다 |
| 못 찾은 논문을 "선행 연구 없음"이라고 쓴다 | 쓴 검색어와 열지 못한 문헌까지 남기고, 못 찾은 것과 없는 것을 따로 적는다 |
| 밤새 돌려 놓으면 아침에 무엇을 했는지 알 수 없다 | 떠나기 전에 맡길 일과 멈출 선을 정하고, 돌아오면 확인을 마친 검토서부터 읽는다 |
| 몇 분째 말이 없어 멈춘 건지 도는 건지 모른다 | 모든 작업이 같은 형식의 진행판에 상태와 마지막 응답 시각을 띄운다 |

## 어떻게 일하나

사람은 정하고 검토합니다. 에이전트는 조사하고, 구현하고, 서로의 결과를 확인합니다.

```
  사람 (낮)                                      에이전트 (밤, 회의, 주말)

  문제를 한 문장으로 고정한다 --+
  판정 기준을 봉인한다          +-- 맡김 지시서 -->  조사, 구현, 집계
  맡길 일과 멈출 곳을 정한다  --+                         |
                                                          v
                                                   다른 에이전트가 다시 계산
                                                          |
  쓸 결과만 골라 받는다       <-- 검토서 ---------  애매한 갈림길은 직접 고르지
  남은 질문에 답한다                                않고 사람에게 묻는다
```

진행은 어느 프로젝트에서나 이렇게 보입니다.

```
== 진행 | demo-study | 선행 연구 정찰과 신규성 판정 | 14:19 (시작 14:02, 경과 17분, 남은 어림 28분) ==
전체   [####--------] 2/5  40%
단계   1 검색어 [완료]  2 정찰 [진행]  3 거리 판정 [예정]  4 검산 [예정]  5 판정 [예정]

에이전트    역할        맡은 일              상태     시작   마지막 신호  진척
scout-a     문헌 정찰   학회 3곳, 2019~      [완료]   14:07  14:18        후보 41
scout-b     문헌 정찰   프리프린트           [진행]   14:07  14:19        34/80

대기   scout-b, 어림 6분, 14:25에 다시 알림
```

## 견본 프로젝트가 보여 주는 것

[`examples/demo-study`](examples/demo-study)는 가상 주제로 일주일을 채운 견본입니다. 주제와 숫자는 지어냈지만 기록은 절차를 그대로 따랐습니다.

- **판정이 갈린 문헌.** 선행 연구마다 내 질문과 얼마나 겹치는지 판정하는데, 다시 확인한 에이전트가 한 편을 더 겹친다고 봤습니다. "판정이 갈리면 더 겹치는 쪽으로 본다"는 규칙을 미리 적어 두었기 때문에 다툼 없이 정리됐습니다. 열지 못한 문헌은 판정하지 않고 숙제로 남겼습니다.
- **밤사이 찾아낸 규칙의 빈틈.** 맡긴 일 3건은 새벽에 모두 끝났고 다른 에이전트의 확인도 통과했습니다. 그 사이 에이전트는 봉인한 규칙이 한 가지 경우를 정하지 않았다는 것을 찾았습니다. 고르는 쪽에 따라 결과가 1.5일 달라지는 문제였습니다. 에이전트는 직접 고르지 않고 질문으로 남겼습니다. 사람은 아침에 18분 검토하며 답을 정했고, 그 답에 맞춰 집계 한 건을 다시 하게 했습니다.

## 시작하기

Claude Code나 Codex에 이 한 줄을 붙여 넣으세요. `<주소>`는 이 저장소의 주소입니다.

```
<주소> 를 클론하고 AGENTS.md를 읽어 줘. 내 연구에 어떻게 쓸 수 있는지 짧게 알려 주고, 지금 내 상황을 물어봐.
```

도구가 [`AGENTS.md`](AGENTS.md)를 읽고 무엇부터 할지 묻습니다. 새 프로젝트 폴더를 만들거나 스킬을 설치하는 일도 그 자리에서 부탁하면 됩니다.

처음에는 스킬 셋이면 충분합니다.

```
 problem-grill       -->  literature-scout     -->  feasibility-gate
 "문제 정리해 줘"         "선행 연구 찾아"          "해볼 만해?"
 문제를 한 문장으로       내 질문과 가장 겹치는     미리 정한 기준으로
 정한다                   논문을 찾는다             할지 접을지 정한다
```

직접 설치하려면 저장소 루트에서 이렇게 합니다. 공통 규칙을 담은 `research-session`은 함께 들어갑니다.

```
ONLY=problem-grill,literature-scout,feasibility-gate code/scripts/install-skills.sh claude
```

스킬을 설치해 두면 세션을 시작할 때 일주일에 한 번 새 판이 있는지 확인해 알려 줍니다. 갱신해도 직접 고친 스킬은 덮어쓰지 않습니다.

스킬 모음 사이트에서 스킬을 하나씩 받아 설치할 수도 있지만 권하지 않습니다. 그렇게 받으면 모든 스킬이 기대는 공통 규칙(`research-session`)이 빠지고, 새 판 확인과 갱신도 되지 않습니다. 이 저장소를 클론해 `install-skills.sh`로 설치하세요.

## 스킬 17개

| 단계 | 스킬 | 이럴 때 |
|---|---|---|
| 착수 | `problem-grill`, `literature-scout`, `feasibility-gate` | 주제를 다듬고, 이미 누가 했는지 보고, 해볼지 정한다 |
| 실행 | `preregister-seal`, `research-batch` | 실험 전에 규칙을 봉인하고, 일을 나눠 맡기고, 자는 동안 돌린다 |
| 확인 | `fact-check` | 숫자와 인용이 원자료와 맞는지 본다 |
| 원고 | `paper-framing`, `paper-quality-loop`, `paper-readability`, `paper-condense` | 초록과 서론을 세우고, 모의 심사를 돌리고, 읽기 쉽게 다듬고, 분량을 맞춘다 |
| 투고 | `submission-package`, `rebuttal` | 투고 묶음을 만들고, 심사평에 답한다 |
| 운영 | `research-scaffold`, `research-session`, `research-portfolio` | 프로젝트 폴더를 만들고, 세션을 열고 닫고, 여러 편을 함께 본다 |
| 문체 | `korean-academic-style`, `english-academic-style` | 국문과 영문 원고의 문체를 다듬는다 |

## 한계

- 한 연구자가 자기 연구에 쓰면서 만든 절차입니다. 여러 사람이 한 저장소를 함께 쓰거나 다른 분야에서 써 본 적은 아직 없습니다.
- 다시 계산하는 데는 시간이 듭니다. 이 단계를 줄이면 결과를 믿을 근거도 그만큼 약해집니다.
- 문체 스킬 둘은 한 사람의 규범입니다. 각자 자기 규범에 맞게 고쳐 쓰시면 됩니다.
